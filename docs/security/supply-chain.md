# Software supply-chain policy

## Reproducible Python graphs

Direct dependencies live in `requirements/{bot,userbot,tools,dev}.in`. The corresponding `.lock` files are generated by `scripts/compile_locks.sh` with `uv`, include hashes, and are the only inputs accepted by CI and production image builds. CI regenerates all four files and fails on any diff.

`bot.lock` and `userbot.lock` are installed with `--require-hashes --no-deps`; development and operator packages never enter those images. Dependency updates must change the relevant input and all regenerated locks in the same pull request.

## Vulnerability and license gates

`pip-audit` checks every lock. Trivy blocks fixed HIGH/CRITICAL findings in bot, userbot, Supervisor, and PostgreSQL images. Gitleaks scans the pull-request commit range and the complete checked-out history. The required `security-static` check aggregates these gates, so a failure blocks merge.

Temporary exceptions live only in `security/vulnerability-exceptions.json`. Each entry requires a vulnerability ID, ecosystem, target, owner, approver, justification, and future expiry date. Expired, duplicate, incomplete, or malformed entries fail CI. Empty exceptions are the normal state.

The dependency license policy rejects AGPL and SSPL families and requires explicit review for missing metadata. Policy changes require a dedicated pull request and operator approval.

## Immutable references and updates

All third-party GitHub Actions use full commit SHAs. Python and PostgreSQL base images use sha256 digests recorded in `security/base-image-digests.txt`. `scripts/check_immutable_references.py` prevents mutable references from returning.

Dependabot groups Python, Action, and Docker updates weekly. The scheduled security workflow also rebuilds and rescans images weekly, which catches newly disclosed vulnerabilities even when source code is unchanged.

## SBOM and provenance

Pushes to `main`, version tags, published releases, and the weekly schedule generate CycloneDX SBOMs for every Python lock and production image. BuildKit runs with `--sbom=true` and `--provenance=mode=max`; its provenance metadata and the SBOMs are uploaded together as release evidence artifacts.

Artifacts are retained for 90 days. Release operators must attach or archive the matching evidence artifact with the deployed image digest and release record.
