# Фаза 9. Архитектура определения победителя и итоговых рассылок

## Цель

Фаза 9 продолжает разделение Telegram-слоя и прикладной логики. Главной целью был
`bot/handlers/auction/winner.py`: файл содержал 2694 строки, 24 Telegram-handler,
SQL-запросы, runtime-DDL, ручные результаты, рассылки, биржевой `/print_ex` и
механику благодарностей администраторам.

Исходный публичный контракт сохранён:

- `from bot.handlers.auction.winner import router`;
- `announce_winner`;
- `_post_rules_under_lot`;
- `_send_notifications`;
- `cmd_print_win`;
- совместимые функции thanks.

## Новая структура

```text
bot/handlers/auction/
├── winner.py                         # тонкий compatibility facade
└── winner_components/
    ├── __init__.py                   # экспорты компонентов
    ├── common.py                     # форматирование, callback constants, shared state
    ├── announcement.py               # автоматический итог и старые win:* callbacks
    ├── print_win.py                  # /print_win, ручной итог, адресные рассылки
    ├── print_exchange.py             # /print_ex и /ex_owners
    └── thanks.py                     # callback благодарности модератору

bot/services/
└── auction_winners.py                # application boundary

bot/repositories/
└── auction_winners.py                # SQL и транзакции winner workflow

migrations/
└── 007_winner_workflows.sql          # постоянная схема winner/thanks
```

`winner.py` уменьшен с 2694 до 81 строки. Он больше не содержит Telegram-handler,
SQL или бизнес-логику, а только подключает четыре дочерних router и предоставляет
старые точки импорта.

## Разделение ответственности

### `announcement.py`

- выбирает победителя по типу аукциона;
- учитывает платную автоставку;
- формирует итоговый комментарий;
- создаёт карточку подтверждения для админ-лога;
- обслуживает старый сценарий корректировки суммы/победителя;
- выполняет старую адресную рассылку `win:send`.

### `print_win.py`

- строит единый контекст результата;
- применяет ручной результат поверх ставок и владельцев;
- формирует пользовательское сообщение;
- отправляет владельцу, победителю или обоим;
- записывает успешные доставки;
- обслуживает мастер ручного результата;
- показывает пропущенные `/print_win` за день.

### `print_exchange.py`

- обслуживает `/print_ex`;
- показывает владельцев карты из одобренных заявок биржи;
- редактирует победителя, цену и ссылку;
- отправляет результаты сделки участникам.

### `thanks.py`

- принимает `win:thanks:*`;
- быстро отвечает callback, чтобы не получить `query is too old`;
- атомарно увеличивает общее число благодарностей;
- отдельно считает уникальных пользователей.

## Service и repository

`AuctionWinnerService` является единственной прикладной границей для новых
winner-handler. Handler больше не импортируют `db.db` и не содержат SQL.

`AuctionWinnerRepository` отвечает за:

- чтение аукциона, владельцев, пользователей и ставок;
- определение данных автоставки и колоды;
- UID-верификацию участников;
- CRUD ручного результата;
- журнал итоговых рассылок;
- выборку пропущенных рассылок;
- данные `/print_ex`;
- атомарный учёт благодарностей.

Старый `bot/services/admin_thanks.py` также переведён на новый service, поэтому
две независимые SQL-реализации thanks больше не расходятся.

## Миграция 007

Runtime-команды `CREATE TABLE` и `ALTER TABLE` удалены из Telegram-handler.
Схема теперь устанавливается миграцией `007_winner_workflows.sql`:

- `auction_win_mailings`;
- `auction_manual_results`;
- `admin_thanks_totals`;
- `admin_thanks_users`;
- ограничение допустимых целей рассылки;
- ограничение неотрицательной ручной цены;
- мягкое добавление `moderator_comment` и `thanks_count` для старых баз.

Это устраняет DDL из пользовательского callback и делает состояние схемы
воспроизводимым при старте приложения.

## Исправленные ошибки

### `/print_win_missed` больше не перехватывается

Старый фильтр:

```python
F.text.startswith("/print_win")
```

совпадал и с `/print_win_missed`. Теперь используется точный:

```python
Command("print_win")
```

### Обратный аукцион

Ручное меню и fallback-рассылка раньше всегда выбирали максимальную ставку.
Теперь `AuctionKind.lowest_bid_wins` передаётся repository, поэтому reverse-лот
использует минимальную ставку.

### FSM-фильтры

Фильтры сообщений проверяют наличие `from_user` до обращения к `id`. Сервисные
или анонимные сообщения больше не вызывают `AttributeError`.

### Уникальные благодарности

Первый клик пользователя определяется через атомарный
`INSERT ... ON CONFLICT DO NOTHING` внутри транзакции. Параллельные клики не
могут дважды увеличить число уникальных пользователей. Чтение totals учитывает
старые варианты регистра и префикса `@`.

### Отправка `/print_ex`

Если победитель задан только username, система сначала пытается разрешить его в
Telegram user id из таблицы `users`. Если пользователь не запускал бота,
интерфейс явно сообщает, что доставка победителю невозможна, вместо ложного
статуса успеха.

## Совместимость
