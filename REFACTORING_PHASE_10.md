# Фаза 10 — декомпозиция `db/db.py`

## Цель

Разделить исторический модуль `db/db.py`, не ломая существующие импорты и поведение проекта. До этой фазы файл содержал 5461 строк, 244 функции, управление пулом соединений, SQL всех предметных областей и вспомогательную бизнес-логику.

## Выполнено

### 1. Тонкий совместимый facade

`db/db.py` сокращён с 5461 до 539 строк. Теперь он:

- инициализирует миграции;
- повторно экспортирует старый публичный API;
- не содержит SQL и бизнес-операций;
- сохраняет существующие импорты `from db.db import ...`.

Сигнатуры предметных функций сохранены, поскольку facade экспортирует исходные функции напрямую, а не заменяет их универсальными `*args/**kwargs`-обёртками.

### 2. Ядро соединения

Добавлен `db/core.py`:

- создание и закрытие `asyncpg.Pool`;
- `fetch`, `fetchrow`, `fetchval`, `fetchall`, `execute`;
- декоратор `require_db_pool`;
- стабильный `PoolProxy` для старых прямых импортов `db_pool`.

`PoolProxy` исправляет старую проблему Python-импорта: `from db.db import db_pool` раньше мог навсегда сохранить значение `None`, даже после создания реального пула в другом модуле.

### 4. Междоменные зависимости

Скрытые обращения между частями старого монолита выявлены статически. Вместо общего wildcard-импорта оставлен минимальный временный мост `db/repositories/_compat.py` из шести функций:

- `_has_column`;
- `_normalize_username`;
- `auction_exists`;
- `get_user`;
- `get_user_by_username`;
- `is_user_uid_banned`.

Импорты этих зависимостей явные. Новые wildcard-зависимости запрещены тестами.

### 5. Направление зависимостей

- Persistence-слой больше не импортирует Telegram handlers.
- Тип владельца вынесен в `db/types.py`.
- 13 application services и Telegram outbox теперь получают пул через `db.core`, а не через legacy-facade.
- Удалён внутренний импорт `from db.db import execute` из card persistence-кода.

### 6. Исправления

- Исправлена проблема устаревшего прямого импорта `db_pool`.
- В market flow проверка живого пула теперь учитывает состояние `PoolProxy`, а не только `pool is not None`.
- Вынесенный `get_auctions_by_day` получил явную зависимость `DATABASE_URL`; раньше она случайно предоставлялась глобальной областью монолита.
- `require_db_pool` использует `functools.wraps`, сохраняя метаданные декорированных функций.

### 7. Инвентаризация legacy API

Добавлены:

- `DB_API_INVENTORY_PHASE_10.md`;
- `db/legacy_api_inventory.json`.

Карта содержит все 235 предметных функций, их новый repository и список файлов, которые всё ещё импортируют функцию через `db.db`.

На момент завершения фазы:

- 155 функций всё ещё имеют статические legacy-импорты;
- это сохранено намеренно для обратной совместимости;
- следующие фазы смогут мигрировать наиболее связанные вызовы в порядке приоритета.

- Боевая PostgreSQL не подключалась.
- Реальный Telegram polling не запускался.
